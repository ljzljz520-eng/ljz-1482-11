# 云溪创作工坊 · 项目创建向导设计文档

本文档说明 CreativeInput 升级为全栈项目创建向导后的核心设计：草稿身份与创建幂等、
本地先写 vs 服务器先建的取舍、参考链接三级校验、事务边界，以及验收场景的应对方式。

---

## 1. 草稿身份与创建幂等

### 1.1 两级身份

| 身份 | 生成方 | 生命周期 | 作用 |
|------|--------|----------|------|
| `draftId`（草稿身份） | 客户端首次打开向导时生成（UUID），写入 localStorage | 跨标签页、跨刷新、跨离线期稳定存在 | 去重同一"创作意图"：同一草稿无论提交多少次，最多产出一个项目 |
| `Idempotency-Key`（请求号） | 客户端每次点击"创建"时与载荷哈希绑定生成 | 重试、断网重放、响应丢失后重发时**复用同一请求号**；内容变更后**必须换新** | 去重同一次"提交动作"：网络重试/离线重放不会创建副本 |

关键约束：

- **draftId 跨标签页共享**：localStorage 是同源多标签页共享的，因此两个标签页打开的是
  同一个 `draftId`。即使两端同时点击创建，服务端 `Project.draftId` 唯一约束保证只有
  一个事务成功，其余请求被引导到"恢复原项目"路径（HTTP 200 + `recovered: true`），
  **绝不产生副本**。
- **请求号与载荷哈希绑定**：客户端计算 `sha256(canonicalJSON(payload))`。内容被修改后
  旧请求号作废（重新生成），从客户端侧避免"同号不同文"；服务端仍独立校验，不信任客户端。
- **成功响应丢失的恢复**：响应在传输中丢失时，客户端用**同一请求号**重发。服务端命中
  `IdempotencyKey` 记录且载荷哈希一致 → 原样返回首次存储的响应（`replayed: true`）。
  即使幂等记录因极端崩溃未写入，`draftId` 唯一约束仍是最后兜底。

### 1.2 服务端幂等判定表

| 场景 | 判定 | 响应 |
|------|------|------|
| 请求号首次出现 + 权限有效 | 事务内创建项目 | 201 `recovered=false` |
| 同请求号 + 同载荷哈希 | 命中幂等记录 | 200 `replayed=true`，返回首个响应 |
| 同请求号 + **不同载荷** | 违反幂等约定 | **409 `IDEMPOTENCY_CONFLICT`** |
| 不同请求号 + 同 draftId（草稿已转化） | 草稿级去重 | 200 `recovered=true`，返回原项目 |
| 并发：两事务同 draftId 同时入库 | 唯一约束兜底，败方恢复 | 200 `recovered=true` |
| 权限在创建瞬间被收回 | 事务前实时校验权限表 | 403 `PERMISSION_REVOKED`（不占用幂等键，恢复后可原样重试） |

### 1.3 创建事务边界（单事务完成）

```
BEGIN
  ├─ 检查草稿状态（已转化 → 直接返回原项目）
  ├─ 补建草稿行（draftId 唯一占用，Project 外键依赖）
  ├─ 创建 Project + 冻结摘要 snapshot（创建后不再随草稿变化）
  ├─ 逐条创建 ReferenceMaterial（同步完成第 1 级格式校验）
  ├─ 为合法链接创建 ParseJob（独立解析队列，同事务入队不丢任务）
  ├─ 关联草稿名下附件（含仍在上传中的，保留其状态）
  ├─ 草稿标记 converted
  └─ 写入 IdempotencyKey（key + 载荷哈希 + 完整响应）
COMMIT
```

解析任务与业务数据同事务落库（事务性发件箱模式），Worker 进程独立轮询消费，
不会出现"项目建好了但解析任务丢了"的窗口。

## 2. 本地先写 vs 服务器先建草稿

| 维度 | 本地先写（local-first） | 服务器先建草稿（server-first） |
|------|------------------------|-------------------------------|
| **离线体验** | ✅ 完整编辑能力：断网可填写、暂存附件（IndexedDB）、创建请求进离线队列，联网后重放 | ❌ 断网即阻塞：连草稿行都建不出来，除非再叠加一套本地缓存（等于回到本地方案） |
| **隐私** | ✅ 内容留在本机，未提交前不出设备；用户清除本机草稿即彻底消失（服务端无副本） | ❌ 敲入即上云： abandoned 草稿也留存服务端，扩大合规与泄露面（GDPR/个保法意义上的"已收集"） |
| **版本合并成本** | ❌ 高：多标签页/多设备并发编辑同一草稿，需要冲突检测（版本号/etag）+ 合并策略（LWW/字段级合并/CRDT），还要处理"本地副本落后于服务端"的回填 | ✅ 低：服务端是唯一事实源，单写者 + 乐观锁即可；但离线编辑一旦允许，合并问题同样回来 |
| **创建一致性** | 需要额外的幂等设计（本方案的两级身份） | 服务端天然掌控时序，实现简单 |
| **存储风险** | 浏览器配额限制（localStorage ~5MB / IndexedDB 按域配额），需降级预案 | 无客户端配额问题，但服务端要承担海量半成品草稿 |

### 本项目的实现：混合式（本地先写编辑缓冲 + 服务端事务创建）

1. **编辑期本地先写**：每次修改 300ms 防抖写入 localStorage；附件文件写入 IndexedDB。
   断网、刷新、关标签页都不丢内容；多标签页通过 `storage` 事件互相同步（同一 draftId）。
2. **云端后台同步**：编辑防抖 1.2s 后 `PUT /drafts/:id`（幂等 upsert + `baseVersion`
   乐观锁）。版本冲突时以服务端为准回填并提示（"已在其他标签页更新"），
   这是本地先写必须支付的合并成本——我们将其限制在"整稿替换 + 用户提示"的低成本档位，
   不做字段级 CRDT（对单用户多标签场景收益不成比例）。
3. **创建时服务端事务**：创建是唯一的一致性边界，走第 1 节的幂等事务。
4. **配额不足降级**：localStorage / IndexedDB 写失败（`QuotaExceededError`）时降级为
   纯内存模式 + 立即云端同步 + 显著横幅提示，绝不让用户以为"已保存"实际没存。
5. **清除本机草稿 ≠ 删除服务器数据**：本机清除只删 localStorage/IndexedDB；
   服务器草稿可通过"从服务器恢复"拉回；已创建的项目完全不受影响。

## 3. 参考链接三级校验

**核心原则：三个级别语义独立，绝不互相推导。尤其"HTTP 请求成功"只代表资源存在，
不代表获得使用授权。**

| 级别 | 内容 | 执行时机 | 结果状态 |
|------|------|----------|----------|
| 1. 格式检查 | URL 语法、协议白名单（仅 http/https）、禁带凭据、长度限制 | 创建事务内同步执行；客户端另有预检 | `valid` / `invalid`（invalid 不进解析队列） |
| 2. 可访问性 | Worker 真实发起 HTTP 探测（HEAD，405 时降级 GET，限量读取 256KB），记录状态码/最终 URL/内容类型；SSRF 防护拦截内网地址 | 独立解析队列异步执行 | `unknown / checking / reachable / unreachable` |
| 3. 使用许可 | 仅依据**许可证据**：① 用户显式授权声明 ② 页面 `<link rel="license">` / meta license / CC 许可链接模式 | 证据驱动，随时可补充 | `unverified / confirmed / rejected` |

- `reachable` 且无任何许可证据 → 许可仍为 `unverified`，UI 明确提示
  "可访问 ≠ 已授权"。
- 用户声明（attest）本身作为证据落库（`licenseEvidence`），可撤销。
- **解析期间改链接**：素材版本号 +1，新链接重新入队；Worker 写回结果前复核版本，
  过期任务标记 `stale` 直接丢弃，不会用旧链接的结果覆盖新链接。

## 4. 验收场景对照

| 验收场景 | 实现 |
|----------|------|
| 异步解析期间改链接 | `PATCH /materials/:id` → 版本 +1 重新入队；Worker 版本护栏丢弃过期结果 |
| 创建时权限被收回 | 权限实时读库校验（非缓存），403 `PERMISSION_REVOKED`；403 不占用幂等键，权限恢复后原请求号可直接重试 |
| 附件仍上传中 | 附件先登记元数据（`uploading`）再传字节；创建事务按当前状态关联；上传完成后自动回填项目关联；脚本页显示"上传中/失败"明确状态 |
| 浏览器配额不足 | safeStorage/IndexedDB 捕获 `QuotaExceededError` → 降级内存模式 + 横幅提示 + 直接云端同步；附件未暂存时标注"未暂存" |
| 脚本页只展示冻结摘要 | `Project.snapshot` 创建时生成，之后无任何更新路径；脚本页只读渲染，不提供编辑入口 |
| 未完成附件有明确状态 | 脚本页附件列表展示 上传中/已上传/失败 状态徽章与错误原因，3s 轮询直至终态 |
| 导航返回保留可恢复编辑 | 编辑即存本机 + 云端同步，路由切换不丢；回到向导自动恢复；跨标签页 storage 事件同步 |
| 清除本机草稿不删服务器项目 | "清除本机草稿"仅清 localStorage/IndexedDB；服务器草稿可恢复，项目不受影响 |

## 5. 离线创建与恢复时序

```
用户点击创建
  ├─ 在线：POST /projects (Idempotency-Key: K)
  │    ├─ 成功 → 进入项目脚本页
  │    ├─ 响应丢失 → 客户端用同一 K 重发 → 200 replayed，恢复原项目
  │    ├─ 403 PERMISSION_REVOKED → 提示并禁用创建，权限恢复后同一 K 重试
  │    └─ 409 IDEMPOTENCY_CONFLICT → 提示内容已被篡改（客户端 bug 防护）
  └─ 离线：{K, payload} 进入 localStorage 发件箱
       └─ online 事件/15s 轮询 → 同一 K 重放 → 服务端幂等去重
```

多标签页并发创建同一草稿：两端 draftId 相同（localStorage 共享），
服务端 `Project.draftId` 唯一约束保证只有一方创建成功，另一方收到 200 + 原项目。
